# RunGTAP 3.75's gtapv7.tab (7.0) vs the official GTAPv7.tab 7.1 (2026-11-03)

**Question:** phase 3a-2 Tasks 7–9 (`corridas_paper.ps1` steps 4, 5, 6b, 7) patch and compile a `gtapv7.tab`. Should they use the official TAB committed in `data/gtap7/gempack_purdue/` (from GTAP's public "Model code" download, `12101.zip`), or the one RunGTAP 3.75 ships in `C:\runGTAP375`?

**Answer:** they are different model versions. Between them, only the welfare decomposition and the reporting indices change. The linear solution changes only through the `Zerodivide` defaults, and only in cells whose denominator is zero. RunGTAP's file is the one its `gtapv7.exe` was compiled from, and that `.exe` made the 66 matrix records. The full diff is [`gtapv7_tab_70_vs_71_2026-11-03.diff`](gtapv7_tab_70_vs_71_2026-11-03.diff).

**Decision (maintainer, 2026-11-03):** phase 3a-2 uses RunGTAP's 7.0, stored unchanged in `data/gtap7/gempack_rungtap375/`. The 7.1 left `data/` (commit 8e9420fb, PR #186) and is tracked in issue #198.

## Size of the diff

`git -c core.autocrlf=false diff --no-index` gives 556 lines added and 479 deleted, in 118 hunks.
- **No final newline in RunGTAP's file.** It ends in `>!` with no line break, while the 7.1 ends in `>!` + CRLF. The `.diff` marks it with `\ No newline at end of file`, and that last line is one of the 479 + 556.
- **Why `core.autocrlf=false`.** With `core.autocrlf=true` (this Windows clone), git converts only the side outside `data/`, and the whole file shows as changed. An earlier version of this `.diff` used `--ignore-cr-at-eol` instead. That gave 555/478 but hid the missing final newline.
- **One edit to the `.diff`:** the RunGTAP side is labelled `a/rungtap375/gtapv7.tab` instead of the local path `C:/runGTAP375/gtapv7.tab`. Nothing else was edited.

## Which statements change

Method: each file is split into TABLO statements, with comments (`! … !`) and labels (`# … #`) removed. Indices bound by `(all,x,…)` or `sum{x,…}` are renamed canonically, so an `s`/`r` → `s`/`d` rename counts as text only.

- **Equations:** an equation is *report-only* when it defines (on the left of `=`) a variable that no other remaining equation uses. The check is repeated until nothing more drops.
- **Formulas:** a formula is report-only when its coefficient never reaches, even through other formulas, a solution equation or an `Update`.

**Equations that touch the solution: none.**

**Report-only equations (23):**
- 18 changed: the welfare decomposition `E_CNTALLEFFCR`, `E_CNTALLEFFR`, `E_CNTQE`, `E_CNTQEA`, `E_CNTQFEER`, `E_CNTQFER`, `E_CNTQFR`, `E_CNTQGR`, `E_CNTQIA`, `E_CNTQMSR`, `E_CNTQOR`, `E_CNTQPR`, `E_CNTQXSR`, `E_CNTTECHR`, `E_CNTTOTR`, `E_EV_ALT`, plus `E_DEL_TBALRY` and `E_VALUEWU`.
- 5 new in 7.1: `E_QPRIV`, `E_QGOV`, `E_QGDPWLD`, `E_PGDPWLD`, `E_VGDPWLD`.

**Formulas that touch the solution: none.**

**Report-only formulas (6):** changed `CNTALLEFFKR`, `VWOU` (now includes `VIP`) and `WELFARE`; new `GDPWLD`, `LEVTPM` and `RNREG`.

**Text only (26):** labels, spacing or renamed bound indices.
- Equations: `E_CNTENDW`, `E_CNTENDWR`, `E_CNTTECH_AMS`, `E_CNTTECH_ATMFSD`, `E_KE`, `E_PIA`, `E_PM_CR`, `E_PPRIV`, `E_PWU`, `E_QMWCOM`, `E_QMWREG`, `E_QOWU`, `E_VMWCOM`.
- Formulas: `BVCB`, `BVXSB`, `FMSHR`, `MFTAX` (`VMFP(C,…)` → `VMFP(c,…)`), `SMT_CR`, `SM_CR`, `SM_CRS`, `TRADE`, `TTAX`, `VMWDATOT`, `VMWDCRALL`, `VTMCOMM`, `VTMD`.

**Can touch the solution: `Zerodivide`.** Every `Zerodivide` statement, counted:

| statement | 7.0 | 7.1 |
|---|---|---|
| `Zerodivide default 0.5` | 10 | — |
| `Zerodivide default RNREG` (`RNREG = 1 / number of regions`) | — | 16 |
| `Zerodivide default 0.0` | — | 1 |
| `Zerodivide off` | 11 | 17 |
| `Zerodivide (zero_by_zero) default 0.5` | 1 | — |
| `Zerodivide (zero_by_zero) default 0` | 1 | — |
| `Zerodivide (zero_by_zero) off` | 1 | — |
| `Zerodivide (nonzero_by_zero) default 0.5` | 8 | — |
| `Zerodivide (nonzero_by_zero) default 0` | 1 | — |
| `Zerodivide (nonzero_by_zero) default RNREG` | — | 2 |
| `Zerodivide (nonzero_by_zero) off` | 1 | — |

- **Zero divided by zero:** where 7.0 gives 0.5, 7.1 gives 1/n (or 0).
- **Nonzero divided by zero:** 7.1 sets a default only twice, where 7.0 does it 8 times (to 0.5) plus once (to 0). Where 7.0 returns 0.5, 7.1 has no default in effect. TABLO then stops with an error instead of returning a value.
- Both differences only matter where a denominator is zero. With zero flows in the data (for example 20x41), 7.1 can change the solution or stop.

**Other differences that do not change the linear solution:**
- `orig_level` added on `pes` (1.0) and `tpm` (`LevTPM`). They only add LEVB/LEVA levels to the `.sl4`.
- Set `CTAX` renamed `ALLTAX`; one `Write` long name changes (`af` → `afa`).
- `gtapv7.sti` lines 169–171: 7.1 substitutes `qxs`/`E_qxs` in the condensation, which RunGTAP has commented out (`!b`, `!qxs`, `!E_qxs`). This is an exact elimination: it changes the size of the system, not the model.

The classification is a variable-graph heuristic, not a proof. Its blind spot is a variable that the closure makes exogenous: see `E_del_tbalry` below.

## The two corrections asked about

- **`E_del_tbalry` (`100 *`): not in RunGTAP's file.** Line 3382 reads `INCOMEWLD * del_tbalry(r) = …`; 7.1 reads `INCOMEWLD * 100 * del_tbalry(r) = …`.
  - In the standard closure `del_tbalry` is endogenous and only reported.
  - In the retired swap closure (`dpsave(r) = del_tbalry(r)`, used by `runs/nus333_compare`, `runs/9x10_compare` and `runs/gempack_20x41_validation`), it is exogenous but unshocked, so the factor multiplies a zero change.
  - It would matter only if `del_tbalry` were shocked.
- **`ENDWMSHR = EVOS / VES`: already in RunGTAP's file** (line 2284), although its history does not list it. 7.1 has the same line (2347).

## Consequence for phase 3a-2

- **With RunGTAP's 7.0 file**, Tasks 7–9 patch exactly the model of the `gtapv7.exe` that made the 66 matrix records and the Burfisher book solutions. Step 4's cross-check against that `.exe`'s `sl4dump.har` is meaningful.
- **With the official 7.1 file:**
  - The welfare decomposition (`CNT*`, `EV_ALT`) is a different model, so those variables would fail the cross-check.
  - The `Zerodivide` defaults can change the solution where the data has zeros.
